# 性能优化对比

## 优化前后的 clone 操作对比

### 场景 1: 数组操作

```lox
var arr = ["hello", "world", "foo", "bar"];
var x = arr[0];
var y = arr[1];
```

**优化前：**
- `arr[0]` 操作会深拷贝整个 "hello" 字符串
- `arr[1]` 操作会深拷贝整个 "world" 字符串
- 每次访问都需要分配新的堆内存

**优化后：**
- `arr[0]` 操作只增加 Rc 的引用计数（原子操作）
- `arr[1]` 操作只增加 Rc 的引用计数（原子操作）
- 不需要额外的堆内存分配

### 场景 2: 全局变量访问

```lox
var message = "Hello, World!";
println(message);
println(message);
println(message);
```

**优化前：**
- 每次 `println(message)` 都会 clone 整个字符串
- 3 次 println = 3 次字符串深拷贝

**优化后：**
- 每次访问只增加引用计数
- 3 次 println = 3 次轻量级的 Rc::clone

### 场景 3: 函数调用

```lox
fun greet(name) {
    return "Hello, " + name;
}

var result = greet("Alice");
```

**优化前：**
- 参数传递时 clone
- 从常量池加载时 clone
- 返回值时 clone

**优化后：**
- 参数、常量加载都只是 Rc::clone
- 只在必要时才进行实际的对象拷贝

## 性能提升估算

对于不同类型的对象，性能提升如下：

| 对象类型 | 优化前开销 | 优化后开销 | 提升比例 |
|---------|----------|----------|---------|
| Number/Boolean | ~20ns | ~10ns | 2x |
| String (10 字符) | ~50ns | ~10ns | 5x |
| String (100 字符) | ~200ns | ~10ns | 20x |
| Array (10 元素) | ~500ns | ~10ns | 50x |
| Array (100 元素) | ~5000ns | ~10ns | 500x |
| Nested structures | 更大 | ~10ns | >1000x |

*注：以上数据为理论估算值，实际性能取决于具体硬件和使用场景*

## 内存使用

### 优化前
```
Object 直接存储 -> 多次拷贝 -> 多份内存占用
```

### 优化后
```
Rc<Object> 引用计数 -> 共享内存 -> 单份内存占用
```

**示例：**
```lox
var big_array = [1, 2, 3, ..., 1000];
var a = big_array;  // 优化前：复制 1000 个元素
var b = big_array;  // 优化前：再复制 1000 个元素
var c = big_array;  // 优化前：又复制 1000 个元素
```

- **优化前**：内存中有 4 份数组（原始 + 3 份拷贝）
- **优化后**：内存中只有 1 份数组，4 个引用指向它

## 总结

通过引入 `Rc<Object>`，我们：
1. ✅ 消除了绝大多数不必要的深拷贝
2. ✅ 减少了内存分配和释放的次数
3. ✅ 降低了内存占用（尤其是大对象）
4. ✅ 提升了整体执行效率（尤其是字符串和数组密集型操作）
5. ✅ 保持了语义不变（外部行为完全一致）

**预期性能提升：**
- CPU 时间：15-50% 提升（取决于工作负载）
- 内存使用：20-60% 减少（取决于对象大小和共享程度）
- 响应时间：更快的单次操作，更少的 GC 暂停
